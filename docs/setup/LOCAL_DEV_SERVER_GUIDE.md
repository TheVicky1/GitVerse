# Local Development Server Guide

`cmd/devserver` runs the GitVerse site and the web handlers on your machine. It serves the static files from `site/` and mounts the same Go handlers that Vercel runs as functions, so you can try UI and sign-in changes without deploying.

This is a different tool from `scripts/serve-preview.cjs` (a Node preview server, started with `node scripts/serve-preview.cjs`, see [CONTRIBUTING.md](../../CONTRIBUTING.md)). This guide covers only the Go dev server.

## What it does

`cmd/devserver/main.go` registers these routes:

| Route | Served by |
| :--- | :--- |
| `/result` | `web.Config.Result` (public report page for `?u=<login>`) |
| `/auth/login` | `web.Config.Login` (starts GitHub sign-in) |
| `/api/private` | `web.Config.Private` (private-check POST from `callback.js`) |
| `/` (everything else) | Files from the `site/` directory, read from disk on each request |

Other details taken from the code:

- It listens on `127.0.0.1:8787`. The address is the constant `addr`; there is no port flag and the server does not read a `PORT` variable.
- It forces `BASE_URL` to `http://localhost:8787`, whatever `.env.local` says.
- Requests with `Accept: text/markdown` for page paths get the Markdown version of the page (the rule `vercel.json` applies in production).
- Static responses get the same security headers as production (`web.SecurityHeaders()`). `/auth/callback` also gets `Referrer-Policy: no-referrer` and `Cache-Control: no-store`.
- It never prints the credentials it loads.

## Prerequisites

- Go (the version in `go.mod`).
- A GitHub OAuth App for development, and a token for the server's read-only calls (see below).

## Create `.env.local`

The server reads `.env.local` from the **current directory**, so start it from the repository root. If the file is missing it exits with an error. `.env.local` is listed in `.gitignore`; never commit it.

`web.FromEnv()` requires all of these, and reports the names of any that are missing:

| Variable | Used for |
| :--- | :--- |
| `GITHUB_CLIENT_ID` | OAuth App client ID |
| `GITHUB_CLIENT_SECRET` | OAuth App client secret |
| `GH_BOT_TOKEN` | Token used for public `/result` checks |
| `STATE_SECRET` | Key that signs the sign-in state cookie; at least 32 bytes (`openssl rand -base64 32`) |
| `BASE_URL` | Required by `FromEnv`; the dev server overrides it with `http://localhost:8787` |

The parser accepts one `KEY=value` per line, skips blank lines and lines starting with `#`, and strips one pair of matching single or double quotes around a value.

```text
# .env.local
GITHUB_CLIENT_ID=<dev oauth app client id>
GITHUB_CLIENT_SECRET=<dev oauth app client secret>
GH_BOT_TOKEN=<token for read-only GitHub calls>
STATE_SECRET=<at least 32 random bytes>
```

In the OAuth App settings, set the authorization callback URL to `http://localhost:8787/auth/callback`. That is the redirect URI the handlers send (`BASE_URL` + `/auth/callback`).

## Run it

From the repository root:

```bash
go run ./cmd/devserver
```

It logs `devserver: http://localhost:8787 (dev OAuth App, site/ from disk)`. Stop it with Ctrl+C.

## Try things out

| What | URL |
| :--- | :--- |
| Home page | <http://localhost:8787/> |
| Check page | <http://localhost:8787/check/> |
| Public report | <http://localhost:8787/result?u=octocat> |
| Start sign-in | <http://localhost:8787/auth/login> |

- `/result` makes live requests: GitHub profile pages, and the GitHub API with `GH_BOT_TOKEN`. It is not served from mock fixtures, so it needs network access and a valid token. `?u=` must be a valid GitHub login, otherwise you get a 400 page.
- `/auth/login` sets a signed `gha_oauth` cookie and redirects to GitHub's consent screen. After you approve, GitHub redirects to `/auth/callback`, a static page that runs `callback.js`, which POSTs the code to `/api/private`. This exercises the real OAuth flow with your dev app; there is no simulated callback.
- On localhost the state cookie is set without the `Secure` flag (the handler checks for `localhost` or `127.0.0.1` in `BASE_URL`), so it works over plain HTTP.

## What reloads and what does not

There is no hot reload and no file watcher.

- Files under `site/` (HTML, CSS, JS) are read from disk per request, so refresh the browser after editing.
- The result and error page templates and the static assets in `internal/webui/` are embedded in the Go binary (`//go:embed`), and the Markdown pages in `web/markdown` are embedded too. After changing them, stop the server and run `go run ./cmd/devserver` again.
- Many files in `site/` are generated by `go run ./cmd/gendocs` (for example `site/achievements.json`, `site/llms.txt`, `site/robots.txt`, `site/sitemap.xml`). Change the generator or its source data, then regenerate, rather than editing generated output by hand.

## Troubleshooting

| Message | Cause |
| :--- | :--- |
| `devserver: open .env.local: ...` | `.env.local` is missing, or you did not start from the repository root |
| `devserver: missing environment: ...` | One or more required variables above is empty or unset |
| `devserver: STATE_SECRET must be at least 32 bytes ...` | The secret is too short |
| `bind: address already in use` | Something else is using port 8787; the port cannot be changed without editing `addr` in `cmd/devserver/main.go` |
